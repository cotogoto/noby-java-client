# AI開発指示（詳細）

## 1. 目的とAGENTS.mdとの役割分担

ルートの `AGENTS.md` は複数のAIコーディングエージェントが最初に読む短い共通ルールである。本書は、本プロジェクト固有の調査順、互換性、外部API、セキュリティ、検証判断を詳述する。矛盾する場合は、より新しい人間の指示を優先し、判断できなければ変更前に確認する。

## 2. 実装前に読むファイル

最低限、次を読む。

1. `AGENTS.md`
2. `README.md`
3. `pom.xml`
4. `docs/requirements.md`
5. `docs/design.md`
6. `docs/api-spec.md`
7. 対象クラスと関連モデル
8. `docs/test-plan.md`

リリース、運用、外部公開に関係する変更では `release.properties` とGitタグも確認する。ただし `release.properties` は過去のMaven Release Plugin実行結果であり、現在の正式手順と決めつけない。

## 3. 変更してよい範囲

人間から実装を依頼された場合に限り、依頼範囲内の次を変更できる。

- `src` のJava実装
- `test` のテスト
- `docs`、`README.md`、`AGENTS.md`
- 明示的に依頼された場合の `pom.xml`

最小差分とし、既存公開APIの互換性を維持する。依存追加、Javaバージョン変更、外部URL変更は人間の確認対象とする。

## 4. 変更してはいけない／自動判断しない範囲

- 実在するAPIキー、メールアドレス、パスワード、トークン、個人情報をソース・テスト・文書・ログへ追加しない。
- NOBY APIの仕様、エラー意味、値域、公開可否を推測で確定しない。
- 本番APIを自動テストから呼ばない。
- リリース、タグ作成、push、deploy、Maven Release Plugin実行を明示依頼なしに行わない。
- 公開クラス、コンストラクタ、メソッド、モデル項目を互換性評価なしに削除・改名しない。
- `pom.xml.releaseBackup` や `release.properties` を現行設定として機械的に更新しない。
- 生成物の `target` やIDEローカル設定をコミット対象にしない。

## 5. 既存パターンに合わせる事項

- Java 11でコンパイル可能な構文を使用する。
- パッケージは `ai.cotogoto.noby` および `ai.cotogoto.noby.model` の既存責務に従う。
- 公開APIにはJavaDocを付け、既存の4スペースインデント、`final` 引数・ローカル変数の傾向に合わせる。
- モデルは現状Lombok `@Data` を使用する。Lombok除去やモデル方式変更は横断的変更として扱う。
- 例外やログへ要求URL全体を含めない。URLには秘密情報が含まれ得る。
- 外部APIの要求・応答変更は `docs/api-spec.md` とテストを同時更新する。

## 6. 実装後に実行するコマンド

対象JDKはPOMに合わせJava 11を優先する。

```powershell
mvn --version
mvn clean verify
git diff --check
git status --short
```

テストがない、環境差で失敗した、外部API認証が必要などの場合は、成功扱いにせず、実行コマンド・失敗箇所・未実行範囲を報告する。Java 21では現行Lombok 1.18.28に起因するコンパイル失敗が確認されている。

## 7. Secrets・個人情報・外部APIキー

- `app_key`、`mail`、`pass`、`token` は秘密情報として扱う。
- `text`、`lat`、`lng` および応答内容は個人情報・機微情報を含み得る。
- 例示には `<APP_KEY>` 等の明確なプレースホルダーを使う。
- エラー本文をログ化する変更では、マスキング、改行等の無害化、長さ制限、ログレベルを設計する。
- 環境変数名や秘密管理方式は現行リポジトリに定義がないため、勝手に標準を確定しない。

## 8. 人間に確認すべき判断

- 公開APIまたは例外型・例外文言の変更
- 接続先URL、HTTPメソッド、クエリ名、認証方式の変更
- Java、Mavenプラグイン、依存ライブラリの更新
- ロガーやテストフレームワークなど新規依存の追加
- タイムアウト、再試行、レスポンス本文保持の既定値
- リリース番号、タグ、JitPack公開、廃止予定API
- 本番またはテスト用外部APIへの実通信
- APIレスポンス・会話データをログやfixtureへ保存する可否

## 9. 推奨ワークフロー

1. 依頼範囲と作業ツリーを確認する。
2. 根拠となる実装・文書・Git差分を読む。
3. 仕様不明点を推測せず列挙し、影響しない範囲を先に進める。
4. 最小差分で変更し、公開互換性と秘密情報を確認する。
5. 単体テストを追加し、外部実サービスを通常テストから隔離する。
6. Java 11環境で検証し、コマンドと結果を報告する。
7. 関連文書を更新し、未確認事項を残す。
