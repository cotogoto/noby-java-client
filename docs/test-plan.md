# テスト計画

## 1. 現在のテスト構成

- テストソースディレクトリはPOMで `test` に変更されている。
- `test/ai/cotogoto/noby/NobyClientTest.java` と `NobyHttpExceptionTest.java` が存在する。
- JUnit 4.13.2をテストスコープで使用する。
- `NobyClientTest` は正常応答、HTTP 200のAPIエラー、HTTP 400の専用例外変換を外部通信なしで検証する。
- `NobyHttpExceptionTest` はステータス、本文、切詰め、メッセージ秘匿、原因例外を検証する。
- mock、fixture、実APIキーは使用しない。
- Maven Surefireにより9件のテストが自動実行される。

## 2. テスト種別

| 種別 | 現状 | 方針 |
|---|---|---|
| コンパイル／パッケージ | Mavenで構成 | Java 11環境で `mvn clean verify` |
| 単体テスト | HTTP応答変換と専用例外の9件 | 変更対象の正常・異常契約を外部通信なしで検証 |
| 外部API結合テスト | なし | テスト用キー・データ・実施許可を得て限定実行 |
| 回帰テスト | 正常変換と既存APIエラーを一部確認 | 未対象の公開APIとモデルを今後追加 |
| UI/E2E | 対象なし | 利用側アプリケーションで実施 |
| DBテスト | 対象なし | DB実装はない |

## 3. 実行コマンド

## 4. 主要機能ごとの確認観点

### `Parameters`

- 追加順どおりに `&` で連結される。
- 空リストは空文字になる。
- 同名パラメータ、空文字、`null` 値の扱い。
- `getParameters` がリストのコピーを返す。
- 予約文字、非ASCII、空白については、このクラスがエンコードしない現行仕様を明示的に確認する。

### `NobyClient` の入力

- `Setting == null` と全項目 `null`。
- 各任意項目を個別・組み合わせで指定。
- `appKey == null`、空文字。
- `message == null`、空文字、日本語、絵文字、予約文字、長文。
- `study`、`persona`、緯度・経度の有効値・境界・範囲外。

### HTTPと応答変換

- HTTP 200の正常JSONが全フィールドへ変換される。
- 省略フィールド、未知フィールド、`null`、空配列を含む正常JSON。
- HTTP 200の `errors` 応答、複数エラー、想定外エラー構造。
- HTTP 400、401/403、404、429、500系。
- 空本文、不正JSON、Content-Type不一致、接続拒否、DNS失敗、TLS失敗、タイムアウト。
- 認証情報や会話文が例外・ログへ漏れない。

### 結果モデル

- `Result` の文字列、数値、リスト、ネストした `Emotion` の対応。
- JSONの命名とJavaプロパティ（例: `commandId`）の実API応答との整合。
- 数値の精度、欠落時のプリミティブ既定値0。

## 5. 正常系・異常系・境界値の優先ケース

1. 必須値のみの正常応答。
2. 全任意項目を指定した正常応答。
3. HTTP 400本文あり（診断可能性を確認）。
4. API `errors` 応答。
5. 予約文字を含む全文字列パラメータ。
6. null・空・長文入力。
7. 429・5xx・通信タイムアウト。
8. 並行実行とクライアント資源解放。

## 6. DB・外部API・認証・権限

- DB: 対象なし。
- 外部API: 実サービスに依存しないモックHTTPサーバーによる再現可能な試験が望ましいが、現状URLが固定されている。
- 認証: `app_key`、`mail`、`pass`、`token` の欠落・不正・失効を確認する。実秘密値をfixtureやログに保存しない。
- 権限: ライブラリ内の認可はない。外部API側の権限エラーの変換を確認する。

## 7. 手動確認が必要な項目

- 正式なテスト用NOBY API環境と認証情報を用いた疎通。
- 現行APIのパラメータ、値域、レスポンススキーマとの一致。
- JitPackから正式タグの成果物を取得・利用できること。
- Java 11のクリーン環境でのビルド。
- 利用側アプリケーションで例外を捕捉し、ユーザー向け応答へ変換できること。

## 8. テスト不足箇所

- 実際のJersey `Response` 読取とクローズを含むHTTP結合テストがない。
- HTTP層を差し替えられず、通信・TLS・タイムアウトの異常再現が難しい。
- 入力バリデーション、URLエンコード、JSONマッピング、例外内容の回帰テストがない。
- タイムアウト、リソース解放、並行利用のテストがない。
- 対応JDKのCIマトリクスおよびCI設定がない。
