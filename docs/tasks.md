# 実装タスク

## 1. 目的と対象範囲

本書は、[requirements.md](requirements.md) の「NOBY APIエラーに関する変更要求」、[design.md](design.md) の「NOBY API HTTPエラー対応の設計案」、[test-plan.md](test-plan.md) を、レビュー可能な実装作業へ分解したものである。

本リポジトリで実施する範囲は、`NobyClient` がHTTP 200以外の応答を受けたとき、公開API互換性と機密性を維持しながら、利用側がステータスとエラー本文を個別に取得できるようにするところまでである。

Alexa応答、利用側エンドポイント、MP3生成・配信、画面、DBは本リポジトリに実装がないため、下記のライブラリ実装タスクへ混在させない。

## 2. 実施順序

```text
TASK-01 ─┬─> TASK-03 ─> TASK-04 ─> TASK-05 ─┬─> TASK-07 ─> TASK-08 ─> TASK-09
         │                                   └─> TASK-06 ───────┘
TASK-02 ─┘

TASK-10（利用側調査）は別リポジトリで実施し、TASK-11、TASK-12へ続く。
```

- TASK-01、TASK-02は調査・意思決定であり、並行実施できる。
- TASK-03以降は、本書に記載した依存順で実施する。
- TASK-10～12は本リポジトリの変更とは別の作業単位とする。

### TASK-01: 外部APIエラー情報と安全要件を確認する

- 種別: 調査
- 責務: HTTPエラー本文を保持・公開するために必要な外部仕様とセキュリティ判断を確定する。
- 対象ファイル:
  - `docs/requirements.md`
  - `docs/design.md`
  - `docs/api-spec.md`
- 前提:
  - NOBY APIの仕様を確認できる資料またはサービス運用者への確認経路があること。
  - 実際の秘密値を収集・文書化しないこと。
- 作業内容:
  1. HTTP 400時のContent-Typeと本文スキーマを確認する。
  2. 400、401、403、404、429、500系の意味と再試行可否を確認する。
  3. エラー本文に認証情報・個人情報が含まれる可能性を確認する。
  4. 本文の最大サイズ、保持上限、超過時の扱いを決定する。
  5. 本文を生のままアクセサーで返すか、限定的な無害化を行うか決定する。
  6. Content-Type、外部リクエスト識別子等を専用例外に含める必要性を判断する。
- 完了条件:
  - 上記6項目が、確認済み仕様または明示的な運用判断として記録されている。
  - 確認できない項目は未決のまま識別され、実装を阻害する項目と阻害しない項目が分離されている。
  - 秘密値や個人情報が文書へ含まれていない。
- 確認コマンド:

