# DB運用・ロールバック

## 1. 結論

このリポジトリにはDB接続、テーブル、DDL、SQL、Entity、Repository、マイグレーション、fixtureが存在しない。本ライブラリ自身のDB運用・DBロールバック手順は「該当なし」である。

## 2. DB構成・主要テーブル

| 項目 | 現行リポジトリ |
|---|---|
| DB製品／接続設定 | なし |
| テーブル | なし |
| 主キー／外部キー／インデックス | なし |
| 重要カラム | なし |
| ORM／Entity／Repository | なし |
| DDL／SQL／マイグレーション | なし |

`Result`、`Setting` 等はAPI境界のJavaモデルであり、DB Entityではない。

## 3. データ更新時の注意点

本ライブラリはローカルDBを更新しない。ただし `Setting.study` はソースコメント上、会話時の学習有無を選択する項目であり、外部NOBY API側でデータ更新が発生する可能性がある。具体的な保存対象、保持期間、削除・復元手順はこのリポジトリから確認できない。

また、`mail`、`pass`、`token`、`lat`、`lng`、会話文は外部へ送信される。個人情報・秘密情報の取り扱いは外部API仕様と利用側システムの規程を確認する。

## 4. マイグレーション方式

該当なし。Flyway、Liquibase、DDL、独自マイグレーションスクリプトはいずれも見つかっていない。

## 5. バックアップ方針

本リポジトリにはDBバックアップ対象がない。外部NOBY APIおよび利用側アプリケーションのデータについては、各運用主体がバックアップ、保持、暗号化、復元試験を定義する必要がある。

## 6. ロールバック手順

### DB

該当なし。本ライブラリのバージョン変更にDBロールバックは伴わない。

### ライブラリ

利用側で問題が発生した場合の一般的な切戻し候補は、依存バージョンを直前に検証済みのタグへ戻し、利用側を再ビルド・再配置することである。ただし正式なリリース／切戻し手順、検証済みバージョン、成果物保管方針は本リポジトリに記載がないため、本番手順として確定しない。

Gitには `v0.7.1` 等のタグがある一方、現行POMは `0.7.2-SNAPSHOT` である。どの版を切戻し先とするかは人間が判断する。

## 7. 戻せない変更

- 外部NOBY API側で学習・保存されたデータの取消可否は未確認。
- 外部API仕様の廃止・変更により旧ライブラリが動作しない可能性がある。
- 利用側が取得結果を別DBへ保存した場合、その更新のロールバックは本リポジトリの範囲外。

## 8. 本番作業前の確認事項

- 対象が本ライブラリ、利用側DB、外部NOBY APIのどれかを明確にする。
- 現行・変更後・切戻し先のライブラリバージョンとJava互換性を確認する。
- 外部API仕様と接続性をテスト環境で確認する。
- 秘密情報を成果物、ログ、コマンド履歴へ残さない。
- 利用側のデータバックアップ、復元試験、メンテナンス時間、監視項目を確認する。
- 外部API側の学習・保存・削除・復元手順をサービス運用者へ確認する。
